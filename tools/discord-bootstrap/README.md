# Discord Bootstrap — Mythweld (DISCORD-M0)

Разовый CLI-инструмент для первичной настройки Discord-сервера сообщества Mythweld:
создаёт категории, каналы, роли и публикует стартовые сообщения EN/RU по команде владельца.

Инструмент **полностью изолирован от сайта MythweldWeb**: собственные `package.json`,
`package-lock.json` и `tsconfig.json`; каталог `tools/` исключён из корневой
TypeScript-сборки сайта; команды сайта (`npm run verify`, `npm run build`, `npm test`)
его не затрагивают. Бот не работает постоянно — процесс запускается владельцем и
завершается после команды.

## Что создаётся

| Категория       | Канал                 | Тип   | Доступ                        |
| --------------- | --------------------- | ----- | ----------------------------- |
| INFORMATION     | `welcome`             | Text  | только чтение (`@everyone`)   |
|                 | `rules`               | Text  | только чтение                 |
|                 | `announcements`       | Text  | только чтение                 |
| FOREVER JOURNEY | `fj-support`          | Forum | темы и ответы для всех        |
|                 | `book-creator`        | Forum | темы и ответы для всех        |
| TALENTFORGE     | `talentforge-support` | Forum | темы и ответы для всех        |
| COMMUNITY       | `general`             | Text  | общение для всех              |
| STAFF           | `mod-log`             | Text  | скрыт; только Moderator и бот |

Роли: `Moderator` (модерирование без Administrator), `Developer` и `Member`
(базовые права, без административных). Существующие каналы, роли и сообщения
инструмент не удаляет, не переименовывает и не перемещает.

Форумы создаются с List View и тегами `Bug`, `Question`, `Feature Request`,
`Resolved` (`Resolved` — moderated, ставить его могут только модераторы).

## Подготовка

### 1. Discord Application и бот

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications) →
   **New Application** → назовите, например, `Mythweld Bootstrap`.
2. Вкладка **Bot**: нажмите **Reset Token** и скопируйте токен. Это значение
   `DISCORD_BOT_TOKEN`. Токен — секрет: не публикуйте его нигде.
3. На той же вкладке **не включайте** Message Content Intent — инструменту он не нужен
   (используется только непривилегированный Intent `Guilds`).
4. Вкладка **General Information**: скопируйте **Application ID** (Client ID) —
   он нужен для invite-ссылки.

### 2. Минимальные права бота и приглашение

Боту нужны шесть серверных прав: `View Channel`, `Send Messages`, `Embed Links`,
`Read Message History`, `Manage Channels`, `Manage Roles`.
**Administrator не нужен и не запрашивается.**

OAuth2 invite URL (подставьте свой Application ID):

```text
https://discord.com/oauth2/authorize?client_id=<APPLICATION_ID>&scope=bot&permissions=268520464
```

Число `268520464` — сумма ровно этих шести прав. Откройте ссылку, выберите сервер
Mythweld и подтвердите приглашение.

### 3. Иерархия ролей

После приглашения откройте **Server Settings → Roles** и перетащите роль бота
(`Mythweld Bootstrap Bot`) **выше** ролей `Moderator`/`Developer`/`Member`.
Без этого бот не сможет настраивать приватные права STAFF — инструмент проверит
это сам и подскажет при запуске.

### 4. Переменные окружения

```bash
cd tools/discord-bootstrap
cp .env.example .env
```

Заполните `.env`:

```text
DISCORD_BOT_TOKEN=<токен из шага 1>
DISCORD_GUILD_ID=<ID сервера>
```

Guild ID копируется так: Discord → Settings → Advanced → включите
**Developer Mode**, затем правый клик по иконке сервера → **Copy Server ID**.

`.env` исключён `.gitignore` и никогда не коммитится. Инструмент не использует
GitHub Actions, GitHub Secrets и не запускается автоматически при push/merge/деплое.

## Запуск

Требуется Node.js 24 (как в корневом `.nvmrc`).

Команды `setup:*` запускают CLI с документированным флагом Node
`--env-file-if-exists=.env`: файл `.env` подхватывается автоматически, а при его
отсутствии запуск продолжается с переменными окружения (они имеют приоритет
над значениями из файла).

```bash
cd tools/discord-bootstrap
npm ci
```

### Dry-run (безопасный просмотр плана)

```bash
npm run setup:dry
```

Подключается к серверу, сравнивает текущую структуру с целевой и печатает план:
что будет создано, что уже существует, какие конфликты найдены. **Ничего не меняет**
(проверяется unit-тестами).

### Apply (применение с подтверждением)

```bash
npm run setup:apply
```

Порядок работы: проверка Guild ID и фактических прав бота → сводка плана →
запрос подтверждения (нужно ввести `YES`; при неинтерактивном запуске отмена) →
создание только отсутствующих элементов → публикация стартовых сообщений → отчёт.

Правила безопасности apply:

- существующие каналы/категории/роли не изменяются и не удаляются;
- при конфликте имени или типа канал пропускается с пояснением (ручное решение);
- стартовые сообщения помечены футером `mythweld-bootstrap/<канал>` — повторный
  запуск не дублирует их и не трогает чужие сообщения;
- сбой одного шага не останавливает независимые шаги; повторный запуск безопасен.

## Ручные шаги после Apply

1. **Обязательный выбор тега в форумах.** Discord API позволяет включить флаг
   «Require a tag when creating a post», но тогда и стартовому посту бота
   потребуется тег, поэтому инструмент этот флаг не ставит. Включите вручную:
   настройка канала → **Overview → Require a tag when creating a post** —
   для `fj-support`, `book-creator`, `talentforge-support`.
2. **Community Settings** (Server Settings → Community): проверьте, что выбраны
   системные каналы (Rules/Guidelines, Community Updates) — инструмент их не
   меняет. Membership Screening и Onboarding настраивайте на своё усмотрение.
3. **Роли участникам** инструмент не выдаёт: назначьте `Moderator` персоналу
   и `Member`/`Developer` — по вашему решению.
4. Если dry-run показал конфликты (например, канал `welcome` существует как
   голосовой) — переименуйте/удалите лишнее или приведите тип канала вручную,
   затем запустите `setup:apply` снова.

## Восстановление после ошибки

- **Прервался apply** — просто запустите `npm run setup:apply` снова: создание
  идемпотентно, всё созданное распознаётся как существующее, сообщения не
  дублируются.
- **«Боту не хватает прав»** — выдайте шесть прав из invite-URL роли бота
  (Server Settings → Roles → роль бота) и повторите запуск.
- **«Роль бота в иерархии ниже»** — перетащите роль бота выше `Moderator`
  (шаг «Иерархия ролей») и повторите запуск.
- **Не удалось проверить историю канала** — сообщение туда не отправляется
  (защита от дублей). Проверьте права `Read Message History`/`View Channel` для
  бота в этом канале и повторите запуск.
- **Что-то создалось лишнее** — удалите элемент вручную в Discord; инструмент
  ничего не удаляет автоматически.

## Отключение бота после настройки

1. Server Settings → **Integrations**/список участников → исключите бота (Kick).
   Или в Developer Portal → приложение → **Bot → Delete Bot**.
2. Роль бота исчезнет сама. Созданные им роли/каналы остаются — при желании
   удалите их вручную.
3. Удалите локальный `.env` (`rm tools/discord-bootstrap/.env`).
4. Токен считается скомпрометированным, если он попал в чужие руки: Developer
   Portal → **Bot → Reset Token**.

## Расширение конфигурации

Все целевые определения — данные, а не код исполнения:

- `src/config.ts` — `TARGET_CONFIG`: категории, каналы, темы, теги форумов;
- `src/permissions.ts` — права ролей и оверрайты каналов;
- `src/messages.ts` — стартовые сообщения EN/RU (ссылки — только подтверждённые
  существующие ресурсы).

Чтобы поддержать новый продукт Mythweld: добавьте категорию/канал в
`TARGET_CONFIG`, при необходимости — сообщение в `messages.ts`, обновите тесты
(`tests/` фиксируют структуру) и прогоните `npm run typecheck && npm test`.
Изменения конфигурации — через Pull Request, как и весь код.

## Проверки (разработка)

```bash
cd tools/discord-bootstrap
npm ci
npm run typecheck   # strict TypeScript
npm test            # Vitest, мокированный Discord API
npm run build       # tsc -> dist/
```

Тесты не выполняют реальных обращений к Discord: используется in-memory фейк
`DiscordApi`, фиксирующий мутации (в dry-run их ноль). Дополнительно smoke-тест
запускает собранный `dist/index.js` дочерним процессом (без токена — до
конфигурационной ошибки, без обращения к Discord), проверяя работоспособность
npm-команд и флага `--env-file-if-exists`. Поиск маркеров стартовых сообщений
постраничный с бюджетом (1000 сообщений канала, 500 архивных тем форума);
если историю не удалось просмотреть полностью, отправка блокируется. Из корня
репозитория работают прежние команды сайта (`npm run verify` и т. д.) — они не
затрагивают этот инструмент.
