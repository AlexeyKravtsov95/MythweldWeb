## 0. Техническая основа без публикации — Issue #29

- `src/i18n/legal.ts` задаёт контракт Privacy / Terms / Contact: метаданные, заголовок, вводные блоки, секции, абзацы, списки и ссылки. Для Privacy/Terms дата вступления в силу — обязательный будущий вход `effectiveDate` в формате `YYYY-MM-DD`; для Contact — утверждённый `email`. Текущая дата и реквизиты по умолчанию не подставляются.
- В `Dictionary` добавлено `legal`: подписи интерфейса переведены в EN/RU, а `legal.pages.privacy/terms/contact` остаются `null` в обоих словарях. Утверждённые тексты в будущем добавляются только туда. Черновики Markdown не импортируются в код сайта.
- `src/components/legal/LegalPage.astro` принимает `locale` и `document` (`privacy`, `terms` или `contact`), читает соответствующую запись словаря и использует `BaseLayout` с нейтральным путём. При `null` рендеринг завершается ошибкой. `LegalBlocks` и `LegalInline` выводят типизированные блоки с экранированием текста; нет raw HTML, гидратации, формы или backend. Оглавление ссылается на заголовки секций; для длинных текстов/email/URL предусмотрены переносы и существующие дизайн-токены.
- `SiteFooter` готов локализовать будущие внутренние ссылки через `localizeHref` → `localizePath`; внешние URL и `mailto:` сохраняются. `null` по-прежнему не создаёт ссылку.
- Примеры существуют только в `tests/fixtures/legal.ts`, компонентные проверки используют Astro Container API без публичного preview-маршрута. Регрессии проверяют локализацию ссылок, отсутствие шести legal-файлов и утечек юридических черновиков/служебных меток в `dist/`.
- В этой задаче не создаются маршруты, не меняются `LEGAL`, `PUBLIC_PATHS`, sitemap и `robots.txt`. По сверке Issue #32 от 2026-11-03 сейчас **5 нейтральных путей × 2 локали = 10 URL**, включая Community. Каркас Issue #29 уже слит в PR #30, шести legal-маршрутов по-прежнему нет. Подготовка компонентов, утверждение текстов, создание маршрутов, merge, deploy и индексация — отдельные этапы; Issue #29 охватывает только первый.

2. Использовать `BaseLayout` с `locale`, нейтральным `path`, локализованными `title` и `description`; ровно один `<h1>`, последовательные заголовки секций, `<html lang>` из словаря. Проверить canonical, hreflang EN/RU и x-default на EN. `LanguageSwitcher` уже использует тот же `path`: переключение должно вести на соответствующий документ, а не главную.
3. В `src/config/legal.ts` после approval установить нейтральные пути `/privacy/`, `/terms/`, `/contact/`. Сохранить типизированность и фильтрацию `null`: отсутствие отдельного одобрения не должно создавать мёртвые ссылки.
4. Сохранить подготовленную в Issue #29 локализацию внутренних legal-путей в `SiteFooter` через `localizeHref(locale, href)` и проверить её на новых собранных страницах. 6. Только вместе с существующими маршрутами добавить `/privacy/`, `/terms/`, `/contact/` в `PUBLIC_PATHS`. Sitemap автоматически получит шесть новых URL: **10 + 6 = 16 основных URL (8 нейтральных путей × 2 локали)**, с парными alternates. Существующие пути: `/`, `/talentforge/`, `/forever-journey/`, `/book-creator/`, `/community/`. Не добавлять markdown, drafts, `/dev/` или 404.
